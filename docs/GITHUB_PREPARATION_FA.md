# آماده‌سازی انتشار در گیت‌هاب

## کدام پوشه را منتشر کنم؟

فایل `TalentFlow-Portfolio-Source.zip` را در پوشه‌ای تازه استخراج کن. بسته با فهرست مشخصی از فایل‌ها ساخته شده و نسخه‌های قدیمی، تنظیمات محرمانه و تاریخچهٔ گیت را شامل نمی‌شود. از پوشهٔ قدیمی پروژه همه‌چیز را یک‌جا آپلود نکن. وجود ZIP به معنی تأیید اتصال ابری نیست.

## قبل از انتشار

1. README و گزارش verification را بخوان و با وضعیت واقعی تطبیق بده.
2. مطمئن شو `.env.local`، پوشهٔ `n8n/local-configured`، رزومهٔ واقعی، اطلاعات تماس و توکن مصاحبه داخل بسته نیست.
3. اسکرین‌شات فقط با دادهٔ ساختگی بگیر؛ نوار آدرس و پنل تنظیمات ممکن است اطلاعات حساس داشته باشند.
4. عمومی یا خصوصی بودن مخزن را انتخاب کن. انتشار عمومی کد به‌تنهایی مجوز استفادهٔ متن‌باز تعیین نمی‌کند؛ اگر چنین قصدی داری، مجوز مناسب انتخاب کن و اعلان‌های مجوز وابستگی‌ها را نگه دار.
5. متن کوتاه معرفی و رزومه در `docs/RESUME.md` آماده است؛ سهم خودت را دقیق توصیف کن.

## آماده‌کردن مخزن محلی

این فرمان‌ها فقط برای **پوشهٔ تازهٔ استخراج‌شده** هستند، نه پوشهٔ قدیمی با فایل‌های شخصی:

```bash
git init
git add .
git diff --cached --stat
git diff --cached
```

قبل از commit، فهرست و محتوا را بررسی کن. اتصال remote و push باید با آدرس واقعی مخزن خودت انجام شود. این مرحله در آماده‌سازی محلی انجام نشده است. رمز عبور یا توکن گیت‌هاب را داخل چت یا کد قرار نده.

## نمایش پروژه

پس از تأیید اتصال n8n، سناریوی راهنمای اجرا را با دادهٔ ساختگی انجام بده و ویدیوی کوتاهی از ساخت شغل تا گزارش بگیر. در توضیح ویدیو مشخص کن کدام سرویس‌ها ماک‌اند. تا قبل از اجرای موفق، آن را «نمونهٔ اولیه با اتصال ابری در انتظار تأیید» معرفی کن.
