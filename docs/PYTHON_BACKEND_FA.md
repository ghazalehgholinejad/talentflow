# اجرای TalentFlow با بک‌اند Python

نسخهٔ مستقل Python در [talentflow-python](https://github.com/ghazalehgholinejad/talentflow-python) قرار دارد. این حالت به حساب n8n نیاز ندارد و داده را در SQLite محلی نگه می‌دارد. ابتدا README آن مخزن را اجرا کن تا سرور روی `127.0.0.1:8000` آماده شود.

در `.env.local` همین پروژه قرار بده:

```dotenv
TALENTFLOW_BACKEND=python
TALENTFLOW_PYTHON_URL=http://127.0.0.1:8000
TALENTFLOW_API_KEY=همان_کلید_تصادفی_بک‌اند_Python
```

کلید باید حداقل ۳۲ نویسهٔ ASCII و در هر دو برنامه دقیقاً یکسان باشد. نام آن را با `NEXT_PUBLIC_` شروع نکن؛ کلید فقط سمت سرور استفاده می‌شود. سپس `npm run dev` را اجرا یا پس از تغییر تنظیمات دوباره راه‌اندازی کن. وارد داشبورد شو و تازه‌سازی را بزن؛ شروع با بانک دادهٔ خالی طبیعی است.

مسیر آزمایش: شغل آزمایشی بساز → شرح را تأیید کن → رزومه‌های ساختگی را وارد و تأیید کن → غربالگری → تأیید انسانی مصاحبه → پاسخ پنج سؤال → گزارش و تصمیم نهایی.

این انتخاب داده‌های قبلی n8n را منتقل یا حذف نمی‌کند؛ SQLite دیتابیس مستقلی است. برای برگشت، `TALENTFLOW_BACKEND=n8n` و تنظیمات قبلی n8n را استفاده کن. اگر متغیر انتخاب بک‌اند تنظیم نشده باشد، رفتار قبلی n8n حفظ می‌شود.

هر دو حالت آموزشی و محلی‌اند. ارزیابی، تولید سؤال و ارسال ایمیل همچنان mock هستند؛ تغییر زبان بک‌اند به معنی اتصال مدل واقعی نیست. وضعیت «متصل» از پاسخ بک‌اند می‌آید، نه صرف انتخاب گزینهٔ Python.
