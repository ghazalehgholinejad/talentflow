# راهنمای توضیح فنی TalentFlow

## مسئلهٔ پروژه

هدف فقط ساخت چند صفحه نیست؛ هر اقدام باید وضعیت معناداری ایجاد کند. تأیید منابع انسانی باید به جلسهٔ مصاحبه برسد و پایان پاسخ‌ها باید به گزارش قابل مشاهده منتهی شود. پیام موفقیت بدون پاسخ معتبر backend کافی نیست.

## از کجا کد را بخوانم؟

1. `app/page.tsx`: ورودی داشبورد.
2. `components/talentflow-v2.tsx`: فرم‌ها و نمایش وضعیت‌ها.
3. `lib/talentflow-client.ts`: درخواست‌های رابط کاربری.
4. `app/api/talentflow/route.ts` و `lib/n8n-gateway.ts`: واسط محلی و کنترل درخواست‌ها.
5. `n8n/source/engine.mjs`: قواعد کسب‌وکار و برنامهٔ تغییر رکوردها.
6. `scripts/generate-v2-workflows.mjs`: ساخت گراف‌های n8n از همان منطق.
7. `components/interview-v2.tsx`: تجربهٔ پاسخ‌دادن به سؤال‌ها.
8. `tests/talentflow-v2.test.mjs`: مثال‌های اجرایی مسیر موفق و حالت‌های نامعتبر.

## یک درخواست چگونه حرکت می‌کند؟

برای تأیید یک کاندیدا، رابط درخواست را به سرور محلی می‌فرستد. واسط با کلید سمت سرور به webhook وصل می‌شود. گردش‌کار پس از احراز درخواست، رکوردها را می‌خواند و قواعد انتقال وضعیت را اجرا می‌کند. تغییرات با نودهای Data Table ذخیره می‌شوند و بعد پاسخ برمی‌گردد. این توضیح مسیر طراحی‌شده در کد است؛ اجرای کامل آن روی حساب ابری هنوز تأیید نشده است.

## چرا n8n؟

مرز مناسبی برای اتصال webhook، ذخیره‌سازی و سرویس‌های بعدی فراهم می‌کند. بخش زیادی از قواعد این پروژه در Code node است؛ پس آن را «کاملاً بدون کد» معرفی نکن. گردش‌کار ۱۰ مسیرهای سایت را داخل خودش دارد و گردش‌کارهای ۰۱ تا ۰۹ ورودی‌های مستقل جایگزین‌اند.

## چرا یک جدول با JSON؟

واردکردن نسخهٔ آزمایشی ساده‌تر می‌شود و انواع رکورد در یک قرارداد مشترک قرار می‌گیرند. هزینهٔ این تصمیم، محدودترشدن جست‌وجوی ساختاری، نبود روابط اجباری و نبود تراکنش چندرکوردی است. جلوگیری از تکرار در منطق برنامه، معادل تضمین exactly-once یا قفل توزیع‌شده نیست.

## هوش مصنوعی دقیقاً کجاست؟

در نسخهٔ فعلی، ارائه‌دهندهٔ واقعی متصل نیست. متن شغل، سؤال‌ها و ارزیابی با قواعد ماک ساخته می‌شوند. امتیازها برای نمایش جریان هستند؛ سنجش معتبر توانایی فرد نیستند. اتصال مدل واقعی نیاز به پیاده‌سازی ارائه‌دهنده، اعتبارسنجی پاسخ، مدیریت خطا و آزمون جداگانه دارد؛ صرفاً قراردادن API key کافی نیست.

## امنیت چه حدی دارد؟

کلید webhook سمت سرور نگه داشته می‌شود، واسط برای اجرای محلی محدود شده و مصاحبه توکن دارد. این‌ها جای ورود کاربران، نقش‌ها، رضایت داوطلب، سیاست نگهداری داده و امنیت استقرار عمومی را نمی‌گیرند. دادهٔ واقعی حساس وارد نکن و لینک توکن‌دار مصاحبه را در اسکرین‌شات عمومی نگذار.

## تست‌ها چه چیزی را ثابت می‌کنند؟

تست‌های منطق، وضعیت‌ها و پاسخ‌های برنامه را در محیط کنترل‌شده بررسی می‌کنند. تست ساختار گراف، اجرای واقعی نود Data Table نیست. build موفق هم اثبات فعال‌بودن webhook نیست. گزارش verification این مرز را مشخص می‌کند؛ live smoke جداگانه روی حساب تنظیم‌شده، رکوردهای آزمایشی ایجاد می‌کند.

## قبل از مصاحبهٔ فنی تمرین کن

- درخواست ساخت شغل را از دکمه تا نود ذخیره‌سازی دنبال کن.
- توضیح بده چرا webhook ثبت‌نشده خطای ۴۰۴ می‌دهد و نباید به موفقیت محلی تبدیل شود.
- یک تست وضعیت نامعتبر را اجرا کن و دلیل رد درخواست را پیدا کن.
- تفاوت متن سؤال ماک، ذخیرهٔ واقعی پاسخ و نمرهٔ نمایشی را توضیح بده.
- محدودیت همزمانی و قدم بعدی خودت برای رفع آن را بیان کن.

هدف حفظ‌کردن جواب نیست؛ بتوانی روی کد مسیر را نشان بدهی و محدودیت را صادقانه توضیح بدهی.
